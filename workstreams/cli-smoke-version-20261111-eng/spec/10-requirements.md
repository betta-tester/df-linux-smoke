# Requirements — CLI-утилита `smoke`: команда `smoke --version`

Документ разворачивает хартию (`00-charter.md`) в проверяемые требования к
поставке. Источник требований — утверждённый customer-слой discovery
(`00-discovery/upstream.md`): идентификаторы `FR-01` и `NFR-01` перенесены
дословно и не переименованы. Требования `FR-02`…`FR-04` и `NFR-02`…`NFR-03`
выведены на этой стадии из интерфейса IF-01, ограничений CON-01…CON-03 и
рисков RK-01, RK-02 хартии; они уточняют, а не расширяют объём: всё, что
перечислено в OUT-01, остаётся за границей.

Единственное поведение продукта, за которое отвечает эта поставка, — ответ на
`smoke --version`. Всё остальное в CLI существует лишь в том минимуме, без
которого этот флаг не работает.

## Scope

В объёме: Python-пакет `smoke` в src-раскладке в репозитории
`betta-tester/df-linux-smoke`, консольная команда `smoke`, флаг `--version`,
один автотест на реальный контракт команды.

Вне объёма (OUT-01 хартии, дословно): проверка наличия обновлений; диагностика
окружения; публикация пакета в PyPI; любые другие подкоманды и флаги, кроме
`--version`.

## Functional Requirements

#### FR-01: `smoke --version` печатает версию из метаданных пакета

**Priority**: Must

Команда `smoke --version` печатает строку `smoke <версия>` из метаданных
установленного пакета и завершается с кодом возврата 0.

- **Acceptance**: `uv run smoke --version` печатает `smoke ` и значение
  `importlib.metadata.version("smoke")`, код выхода 0.
- **Контракт**: вход — `argv`; выход — stdout и код возврата. На stdout не
  печатается ничего, кроме одной строки версии; диагностика, если она
  появится, идёт на stderr.
- **Источник**: `00-discovery/upstream.md` (FR-01), перенесён без изменений.
- **Traces**: G-01, J-01, P-01, P-02.

#### FR-02: Команда `smoke` доступна как установленный entry point

**Priority**: Must

После установки дистрибутива в окружении доступна консольная команда `smoke`:
пользователь вызывает `smoke`, а не `python -m …` и не путь к файлу в
исходниках.

- **Ограничение**: команда объявляется entry point в `[project.scripts]`
  файла `pyproject.toml` — решение хартии (FR-01, «Интерфейс»), здесь не
  переоткрывается.

- **Acceptance**: после `uv sync` вызов `uv run smoke --version` завершается
  успешно без указания пути к модулю; имя команды в выводе `--version`
  совпадает с именем пакета (`smoke`).
- **Rationale**: без этого FR-01 недостижим для P-02, который получает
  инструкцию «запусти одну команду» и не работает с исходниками.
- **Источник**: выведено из IF-01 и раздела «Интерфейс» FR-01 хартии.
- **Traces**: FR-01, J-01, P-02, CON-01.

#### FR-03: Поведение `smoke` без аргументов не мешает основному сценарию

**Priority**: Should

Запуск `smoke` без аргументов не должен выглядеть как успешный ответ на
`--version`: строка `smoke <версия>` в этом случае на stdout не печатается.
Предлагаемое по умолчанию поведение — стандартное поведение `argparse`: usage
на stderr. Окончательный выбор между «usage с кодом 0» и «usage с кодом 2»
принимается на стадии design (см. Q-01).

- **Acceptance**: `uv run smoke` без аргументов не печатает на stdout строку
  вида `smoke <версия>`, а печатает usage на stderr.
- **Rationale**: P-02 копирует вывод в тикет как есть; случайный запуск без
  флага не должен давать текст, который выглядит как версия.
- **Источник**: Q-01 хартии (вопрос остаётся открытым, адресат — architects).
- **Traces**: FR-01, OUT-01, P-02.

#### FR-04: Версия никогда не выдумывается

**Priority**: Must

Единственный источник значения версии — метаданные установленного дистрибутива.
Если версию получить нельзя (дистрибутив не установлен в текущем окружении),
команда не печатает на stdout никакое значение версии — ни литерал из кода, ни
значение, вычитанное из рабочей копии — и завершается с ненулевым кодом
возврата. Форма сообщения об этой ошибке решается на стадии design (см. Q-02).

- **Acceptance**: в окружении, где дистрибутив `smoke` не установлен, вызов
  команды не печатает на stdout строку вида `smoke <версия>` и возвращает
  ненулевой код.
- **Rationale**: прямая защита G-01 и митигация RK-01/RK-02 — молчаливый
  fallback на захардкоженное значение вернул бы ровно ту проблему, ради
  которой заводилась команда: версия угадана, а не известна.
- **Источник**: выведено из RK-01, RK-02 и CON-01 хартии.
- **Traces**: FR-01, G-01, CON-01.

## Non-Functional

#### NFR-01: Быстрый ответ, без сети и без записи на диск

**Priority**: Must

Ответ быстрее 1 секунды; без обращений к сети и без записи на диск.

- **Target**: время ответа < 1 с; 0 сетевых вызовов; 0 записей на диск.
- **Источник**: `00-discovery/upstream.md` (NFR-01); условие о стандартной
  библиотеке — свойство реализации, оно в CON-02.
- **Traces**: FR-01, CON-02.

#### NFR-02: Вывод пригоден для копипаста без правок

**Priority**: Must

Формат вывода `--version` — одна строка `smoke <версия>`, завершённая переводом
строки, без рамок, баннеров, цвета, ANSI-escape-последовательностей и
приглашений к действию. Формат стабилен: он не меняется между запусками и не
зависит от того, подключён ли stdout к терминалу или к пайпу.

- **Target**: вывод при `isatty() == True` и при перенаправлении в файл или
  пайп побайтово совпадает; строк на stdout ровно одна.
- **Rationale**: J-01 требует вывод, который P-02 вставляет в тикет без правок
  и без пояснений; нестабильный или украшенный вывод ломает и копипаст, и
  ручную разметку по M-01.
- **Источник**: выведено из J-01, P-02 и раздела «Интерфейс» FR-01 хартии.
- **Traces**: FR-01, J-01, M-01.

#### NFR-03: Смена версии видна в выводе без иных правок

**Priority**: Must

После изменения поля `version` в `pyproject.toml` и `uv sync` команда
`uv run smoke --version` печатает новую версию; другие файлы для этого
менять не нужно.

- **Target**: в 100% проверок после bump версии и `uv sync` вывод
  `smoke --version` равен `smoke <новая версия>`.
- **Rationale**: G-01 и митигация RK-02 — версия, которую нужно править в
  нескольких местах, рано или поздно разойдётся с выпущенной, и P-02 вставит
  в тикет не ту версию.
- **Источник**: CON-03, RK-01, RK-02 хартии.
- **Traces**: FR-01, FR-04, CON-01, CON-03.

## Constraints

Ограничения хартии действуют без изменений и в этом документе не
переформулируются:

- **CON-01** — Python 3.12+, `uv`, `pytest`, src-раскладка; имя пакета и
  команды `smoke`; версия объявлена ровно в одном месте — в `pyproject.toml`.
- **CON-02** — в рантайме только стандартная библиотека; без сети и без записи
  на диск; `uv` и `pytest` остаются инструментами разработки.
- **CON-03** — `argparse` и `importlib.metadata.version("smoke")`; без `click`,
  `typer` и прочих CLI-фреймворков; тесты через `subprocess`. Ожидаемый объём —
  один модуль и один тест.

## Assumptions

- **A-01** Окружение, в котором запускается команда, создаётся через `uv sync`,
  поэтому дистрибутив `smoke` в нём установлен. Сценарий «запуск из исходников
  без установки» считается ошибкой использования, а не поддерживаемым режимом
  (RK-01); FR-04 ограничивает ущерб от этой ошибки.
- **A-02** Значение версии в `pyproject.toml` поддерживает владелец репозитория
  вручную; автоматический bump, теги и релизный процесс в объём не входят.
- **A-03** M-01 измеряется ручной разметкой входящих баг-репортов владельцем
  репозитория; базовая линия 0% зафиксирована на 2026-11-11.

## Open Questions

Вопросы Q-01 и Q-02 перенесены из хартии без изменения смысла и переадресованы
стадии design; Q-03 и Q-04 заведены здесь. Блокирующих вопросов нет: FR-01
реализуем при любом из предложенных ответов.

- **Q-01 · owner_role: architects · blocking: false.** Что делает `smoke`,
  запущенный без аргументов: печатает usage с кодом 0, печатает usage с кодом 2
  (поведение `argparse` по умолчанию) или печатает то же, что `--version`?
  Предлагаемый по умолчанию ответ — стандартное поведение `argparse`: usage на
  stderr, остальное вне объёма по OUT-01. Ответ фиксирует acceptance для FR-03.
- **Q-02 · owner_role: architects · blocking: false.** Нужно ли перехватывать
  `PackageNotFoundError` и печатать понятное сообщение с ненулевым кодом
  возврата, или достаточно процессной митигации RK-01 (запуск только через
  `uv run` после `uv sync`)? Перехват добавляет код и ветку тестов сверх «одного
  модуля и одного теста» из CON-03. FR-04 обязателен при любом ответе; вопрос
  только в форме сообщения.
- **Q-03 · owner_role: architects · blocking: false.** Достаточно ли одного
  subprocess-теста, чтобы покрыть FR-01, FR-02 и NFR-02, или проверки stdout,
  кода возврата и стабильности вывода при перенаправлении нужно развести по
  отдельным тестам? Решение влияет на оценку объёма «один модуль и один тест»
  из CON-03.
- **Q-04 · owner_role: product · blocking: false.** Какое значение версии
  проставить в `pyproject.toml` при первой поставке — `0.0.0`, `0.1.0` или
  иное? На FR-01 не влияет (версия читается из метаданных), но попадает в
  первые баг-репорты, по которым считается базовая линия M-01.
