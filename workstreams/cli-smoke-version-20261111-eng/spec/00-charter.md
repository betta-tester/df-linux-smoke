# Charter — CLI-утилита `smoke`: команда `smoke --version`

Хартия сводит два слоя discovery в один управляющий документ: утверждённый
customer-фрейм (`00-discovery/upstream.md`, источник требований — все `FR-NN` и
`NFR-NN` перенесены дословно и без переименования) и инженерный фрейм
(`00-discovery/brief.md`, система, интерфейсы, архитектурные предпочтения,
риски). Оба источника объявлены прямыми рёбрами `traces_to` и закреплены
git-блобами в `upstream_hashes`.

Предмет: в пустом репозитории `betta-tester/df-linux-smoke` появляется Python-пакет
`smoke` в src-раскладке с единственной консольной командой `smoke`, у которой
реализован флаг `--version`.

## Goals

#### G-01: Точная версия пакета при разборе бага

При разборе баг-репорта версия установленного пакета известна точно, а не
угадывается по косвенным признакам (дате, ветке, словам репортёра). Источник
истины — метаданные установленного дистрибутива, а не то, что лежит в рабочей
копии разработчика. Прогресс по цели измеряется метрикой M-01.

## Personas

#### P-01: Разработчик, разбирающий баг-репорты

Primary. Получает баг-репорт, должен за один шаг установить, какая версия
`smoke` воспроизводит проблему, прежде чем тратить время на воспроизведение.
Работает в терминале, читает stdout и коды возврата.

#### P-02: Пользователь, запускающий команду

Secondary. Запускает команду у себя и пересылает вывод как есть — копипастом в
тикет или чат. Не обязан понимать, откуда берётся версия, и не должен выполнять
дополнительных шагов, чтобы её получить.

## Jobs-to-be-done

#### J-01: Узнать установленную версию одной командой

Когда приходит баг-репорт, P-01 (или по его просьбе P-02) хочет одной командой
узнать точную установленную версию `smoke`, чтобы вывод можно было вставить в
тикет без правок и без пояснений.

## Functional Requirements

#### FR-01: `smoke --version` печатает версию из метаданных пакета

Команда `smoke --version` печатает строку `smoke <версия>` из метаданных
установленного пакета и завершается с кодом возврата 0.

- **Priority**: Must
- **Acceptance**: `uv run smoke --version` печатает `smoke ` и значение
  `importlib.metadata.version("smoke")`, код выхода 0.
- **Traces**: G-01, J-01 (источник: `00-discovery/upstream.md`)
- **Интерфейс**: консольная команда `smoke`, объявленная как entry point в
  `[project.scripts]`; вход — `argv`, выход — stdout и код возврата. Ничего,
  кроме строки версии, на stdout не печатается.

Реализация ограничена CON-01, CON-02 и CON-03; поведение при ненайденном
дистрибутиве разобрано в RK-01, вопрос о запуске без флагов — Q-01.

## Non-Functional

#### NFR-01: Быстрый ответ, без сети и без записи на диск

Ответ быстрее 1 секунды; без обращений к сети и без записи на диск; только
стандартная библиотека Python 3.12+.

- **Target**: время ответа < 1 с; 0 сетевых вызовов; 0 записей на диск.
- **Traces**: FR-01 (источник: `00-discovery/upstream.md`)

Запрет на сторонние рантайм-зависимости, который делает этот таргет достижимым,
зафиксирован отдельно как CON-02.

## Constraints

#### CON-01: Платформа, инструменты и раскладка проекта

Python 3.12+; управление зависимостями и запуск — `uv`; тесты — `pytest`;
src-раскладка пакета. Имя пакета и имя консольной команды — `smoke`. Версия
объявляется ровно в одном месте — в `pyproject.toml`; дублировать её в коде,
тестах или документации запрещено.

Ограничение сводит воедино `CON-01` обоих слоёв discovery
(`00-discovery/upstream.md` и `00-discovery/brief.md`): они не конфликтуют, а
дополняют друг друга, поэтому в хартии им соответствует один адрес. Инженерная
часть, не покрытая этим пунктом, вынесена в CON-02 и CON-03.

#### CON-02: Только стандартная библиотека в рантайме

В рантайме нет сторонних зависимостей: исполняемый код опирается только на
стандартную библиотеку Python 3.12+. Команда не ходит в сеть и ничего не пишет
на диск. `pytest` и `uv` — инструменты разработки, в рантайм-зависимости пакета
они не попадают.

Источник: `00-discovery/brief.md` (CON-01, инженерный фрейм); согласуется с
таргетом NFR-01.

#### CON-03: argparse и importlib.metadata, без CLI-фреймворков

Разбор аргументов — `argparse`; получение версии — `importlib.metadata.version("smoke")`.
`click`, `typer` и прочие CLI-фреймворки не используются. Тесты вызывают
установленную команду через `subprocess`, а не импортируют внутренние функции,
чтобы проверялся реальный контракт FR-01 (argv → stdout + код возврата).

Источник: `00-discovery/brief.md` (AP-01). Feasibility-оценка инженерного слоя:
FR-01 реализуем полностью, объём — один модуль и один тест.

#### OUT-01: Проверка обновлений, диагностика, публикация, другие команды

Вне объёма: проверка наличия обновлений; диагностика окружения; публикация

## Risks

#### RK-01: PackageNotFoundError при неустановленном пакете

`importlib.metadata.version("smoke")` выбрасывает `PackageNotFoundError`, если
дистрибутив не установлен в текущем окружении. Тогда FR-01 нарушается: вместо
строки версии пользователь получает traceback и ненулевой код возврата.

- **Вероятность/влияние**: высокая / среднее — срабатывает при запуске из
  исходников без установки.
- **Митигация**: тесты запускаются только после `uv sync`, через `uv run`, то
  есть против установленного дистрибутива; это же требование фиксируется в
  инструкции по запуску.
- Источник: `00-discovery/brief.md` (RK-01).

#### RK-02: Расхождение версии между `pyproject.toml` и тестами

Если ожидаемое значение версии будет захардкожено в тесте или в коде, очередной
bump версии оставит проект в состоянии «тесты красные, хотя поведение верное»,
а в худшем случае — «версия в выводе не та, что в метаданных». Это прямо
нарушает CON-01.

- **Вероятность/влияние**: средняя / среднее.
- **Митигация**: тест сверяет вывод команды с `importlib.metadata.version("smoke")`,
  вычисленным в момент прогона, а не со строковым литералом.
- Производный риск: в слоях discovery не зафиксирован, выведен из CON-01.

#### Q-01: Поведение `smoke` без аргументов

FR-01 и IF-01 описывают только `--version`. Что делает `smoke`, запущенный без
аргументов: печатает usage с кодом 0, печатает usage с кодом 2 (поведение
argparse по умолчанию для обязательных аргументов) или печатает то же, что
`--version`? Предлагаемый по умолчанию ответ: стандартное поведение argparse —
usage на stderr, остальное вне объёма по OUT-01.

- Не блокирующий. Адресат: декомпозиция.

#### Q-02: Нужен ли явный дружелюбный ответ на ненайденный дистрибутив

Нужно ли перехватывать `PackageNotFoundError` и печатать понятное сообщение с
ненулевым кодом возврата, или достаточно процессной митигации RK-01 (запуск
только через `uv run` после `uv sync`)? Перехват добавляет код и ветку тестов
сверх «одного модуля и одного теста» из CON-03.

- Не блокирующий. Адресат: декомпозиция.
