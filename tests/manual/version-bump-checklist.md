# Проверка bump версии (BEH-09)

Ручная проверка: смена `version` в `pyproject.toml` видна в выводе
`smoke --version` без каких-либо иных правок. Документ самодостаточен —
обращаться к спецификации не нужно.

**Отказ** — любое из двух: после `uv sync` в выводе осталась старая версия, или
пришлось тронуть файл помимо `pyproject.toml` (кроме `uv.lock`, см. шаг 5).

## Подготовка

- Чистое рабочее дерево: `git status --short` ничего не выводит.
- Команды выполняются из корня репозитория, только через `uv`.
- Запишите исходную строку версии `version = "..."` из `pyproject.toml`.
- Выберите `версия-B` — любое значение, отличное от текущего (например, текущая
  `0.1.0` → `0.1.1`).

## Шаги

1. **Вывод до правки.** Выполните:

   ```bash
   uv sync
   uv run smoke --version
   ```

   Ожидается одна строка `smoke <версия-A>`. Запишите её в поле A ниже.

2. **Правка.** Измените в `pyproject.toml` только значение `version` на
   `версия-B`. Больше ничего не правьте (ни код, ни тесты, ни документацию).

3. **Diff `pyproject.toml`.** Выполните `git diff pyproject.toml` и вставьте
   вывод в поле «Diff». В нём должна быть ровно одна изменённая строка
   `version`.

4. **Вывод после `uv sync`.** Выполните:

   ```bash
   uv sync
   uv run smoke --version
   ```

   Ожидается `smoke <версия-B>`. Запишите вывод в поле B ниже.

5. **Список изменённых файлов.** Выполните `git status --short` и вставьте
   вывод в поле «Файлы». Допустимо ровно:
   - `pyproject.toml` — ваша правка;
   - `uv.lock` — `uv sync` сам перезаписывает в нём версию пакета `smoke`;
     это генерируемый файл, а не код, проверки или документация. Если файла в
     списке нет — тоже нормально.

   Любой другой файл (код, тесты, документация) — отказ.

6. **Сверка.** Убедитесь, что `версия-B` в выводе шага 4 совпадает с
   значением, вписанным в `pyproject.toml` на шаге 2, и отличается от
   `версия-A`.

7. **Откат.** Верните рабочее дерево к исходному состоянию:

   ```bash
   git checkout -- pyproject.toml uv.lock
   uv sync
   ```

   Не коммитьте bump.
